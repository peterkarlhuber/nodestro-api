# {title}

This folder is the Nodestro workflow **{title}** as a ready-to-run application for **{platform}**. It brings
everything it needs: its own Python, every library, the workflow (release **v{number}**, workflow version
v{version}, published {published}, digest `{digest}`){local_models_line} and, when it was exported with one, a
web interface. Nothing needs to be installed: no Python, no pip, no Node.js and no Nodestro Studio.

## Start

1. Unpack the ZIP file into a folder you can write to (for example your documents folder). The path should not
   be too long on Windows; `C:\Apps\` works well.
2. Start the application:
   - **Windows:** double-click `start.cmd`.
   - **macOS:** double-click `Start.command` (the first time: right-click, "Open", because the file was downloaded).
   - **Linux:** run `./start.sh` in a terminal.
3. The first start checks the files{models_check}. When it is ready, the window shows the address
   (`http://127.0.0.1:{port}`) and opens the browser{ui_line}.

Stop the application with **Ctrl+C** in its window, or with `stop.cmd` / `./stop.sh`. Starting it again keeps
every run, approval, file and setting.

| Command (`start.cmd …` on Windows, `./start.sh …` elsewhere) | What it does |
| --- | --- |
| `start` (or nothing) | Starts the application. |
| `stop` | Stops a running instance. |
| `status` | Tells whether it runs, and where. |
| `open` | Opens the browser with a new sign-in link (only on this computer). |
| `configure` | Enters the keys of the AI providers (input is hidden). |
| `keys new --name "My app" --scopes run,read` | Creates an API key for another program (`keys list`, `keys revoke <id>`). |
| `check` | A self-test without starting (`check --full` also checks every model file by SHA-256). |

## AI providers and keys

{providers_section}

Keys are never part of this package. Enter them in the browser (Settings, only for the operator of this computer)
or with `configure` in a terminal; both store them in `data/secrets/providers.json`, readable only by your user
account. The file is not encrypted (an encryption key next to it would protect nothing): protect it like an SSH
key, or set the keys as environment variables from a secret store instead. Environment variables always win.
A changed key applies to the next run; no new export is needed.

## Result files

{output_section}

Every run also keeps its files in the application (download them in the browser or with
`GET /runs/{run_id}/files/{file_id}`). The browser cannot choose folders on this computer: the folder is set by the
operator in `config/settings.toml` (`[data] output_dir`, relative to this folder or absolute). File names are made
safe for every system; a name that exists already gets ` (2)`, ` (3)` …

## Settings

`config/settings.toml` holds every setting with explanations (port, address, folders, limits, model memory,
offline mode, interface language). Changes apply at the next start. Environment variables override the file (for
example `PORT`, `DATA_DIR`, `OUTPUT_DIR`).

By default the application answers **only this computer** (`127.0.0.1`). To serve other computers set
`host = "0.0.0.0"` **and** HTTPS (`tls_cert`/`tls_key`, or `behind_proxy = true` behind a reverse proxy with
HTTPS); without HTTPS it refuses to start that way. Other people sign in with an API key; nobody can sign in
without one.

Runs are asynchronous: starting answers `202` with a `run_id`. Status values: `queued`, `running`,
`awaiting_approval`, `succeeded`, `failed`, `cancelled`. The events are Server-Sent Events; after a lost connection,
reconnect with `Last-Event-ID`. This workflow has {approvals}; a key with the permission `approve` decides:

```bash
{curl_approve}
```

Errors have the form `{"error": {"status", "code", "message", "params"}}`. The complete description is
`openapi.json` in this folder (OpenAPI 3); the interactive reference is `http://127.0.0.1:{port}/docs` (only from
this computer by default). `examples/client.py` shows everything in Python.

## Security

- No key of Nodestro or of an AI provider is in this package, and the browser never receives a provider key.
- The web interface uses a session cookie (HttpOnly, SameSite=Strict); the operator signs in with a one-time link
  from the start window, everybody else with an API key.
- Tools that a person wrote run as separate processes. Tools generated by AI run only in an isolated Docker
  container (`[tools] sandbox = "docker"`, Docker required); without Docker, runs that need them are refused and
  nothing runs unprotected.
- The local model server listens on `127.0.0.1` only, on a port of its own.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The port is in use | Set another `port` in `config/settings.toml`, or stop the other instance (`stop`). |
| "Missing keys" in the interface | Enter them under Settings, or run `configure`. |
| A run fails at once | Open the run in the interface; its steps show the reason. `logs/application.log` has details. |
| Very slow answers | Local models without a graphics card are slow; see "Local models" for the memory each needs. |
| macOS: "cannot be opened" | Right-click `Start.command`, "Open"; or run `xattr -dr com.apple.quarantine .` in this folder. |
| Windows SmartScreen | "More info", "Run anyway" (the scripts are plain text you can read). |
| Something else | `check` tests the package; `logs/` has the logs of the application and the model server. |
